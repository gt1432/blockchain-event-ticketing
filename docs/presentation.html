Industry Crisis

The Broken Ticketing Ecosystem: Problem Statement

1. Predatory Bot Scalping

Automated bot cartels deplete primary inventory in seconds. Tickets are subsequently marked up 300% to 1,000% on secondary black markets, pricing out genuine fans.

2. Counterfeiting & Fake PDFs

Static PDF tickets and screenshots are duplicated and sold to multiple victims. At venue gates, duplicate barcode scans trigger entry denial and fan disputes.

3. Black-Market Circumvention

Existing ticketing sites lack contract-level enforcement. Once tickets are transferred off-platform via email, organizers lose all oversight and price control.

4. Monopolistic Control & Hidden Fees

Centralized conglomerates extract 25% to 40% hidden "convenience" and delivery fees while holding opaque control over inventory distributions.

Project Mission

Project Objectives & Technical Scope

1. Smart Contract Price Caps

Mathematically restrict secondary resale transactions to an organizer-configured maximum price (P_resale ≤ P_max). Prevent extortionate markups directly at the EVM bytecode level.

2. Peer-to-Peer Transfer Lock

Override the ERC-721 _update hook to forbid direct wallet-to-wallet transfers, ensuring all secondary transactions are audited and settled through the on-chain resale marketplace.

3. Cryptographic Gate Access Control

Provide venue staff with a camera-based scanner verifying dynamic QR payloads against the blockchain state. Execute an atomic single-use redemption that permanently prevents duplicate entry.

4. Zero-Friction User Experience

Seamlessly bridge Web2 and Web3 by integrating both native MetaMask browser connectivity and an instant In-Browser 1-Click Demo Wallet for presentations without gas or extension requirements.

Core Protocol Logic

Smart Contract Design & Anti-Scalping Mathematical Model

Mathematical Price Ceiling Predicate

Let an event E have original ticket face value P_primary in wei. The organizer establishes an immutable maximum resale ceiling P_max during event creation:

P_max ≥ P_primary
ValidateListing(T_i, P_resale) = (P_primary ≤ P_resale ≤ P_max) ∧ (¬isRedeemed(T_i))

If P_resale > P_max, the transaction reverts on-chain with ResalePriceExceedsMaximumAllowed().

P2P Transfer Restriction Hook

Direct wallet-to-wallet transfers are locked via the custom ERC-721 _update hook to prevent off-chain cash deals:

function _update(address to, uint256 tokenId, address auth) internal override returns (address) {
  address from = _ownerOf(tokenId);
  if (from != address(0) && to != address(0)) {
    if (!_transferAllowed) revert UnauthorizedTicketTransfer();
  }
  return super._update(to, tokenId, auth);
}
Gate Access Control

Cryptographic QR Verification & 5-State Machine

STATE 1: VALID

Entrance Approved

Token exists, event matches, owner verified, isRedeemed == false. Staff redeems pass.

STATE 2: ALREADY USED

Duplicate Entry Denied

isRedeemed == true. The pass was already checked in. Stops copied QR screenshot fraud.

STATE 3: WRONG EVENT

Event Mismatch

Token exists on blockchain, but was issued for a different event than current gate.

STATE 4: INVALID TICKET

Counterfeit Barcode

Token ID does not exist on the smart contract. Fake ticket detected immediately.

STATE 5: UNAUTHORIZED

Verifier Role Required

Scanner caller lacks VERIFIER_ROLE on contract. Prevents unauthorized burns.

ATOMIC REDEMPTION

Permanent Single-Use

Calling redeemTicket(tokenId) permanently marks the pass used on Ethereum.

Secondary Market

Anti-Scalping Resale Marketplace Mechanics

1

Owner Listing

Only the current verified owner of an unredeemed ticket can list it for secondary resale.

2

Ceiling Audit

Contract verifies that asking price does not exceed organizer's maximum resale cap.

3

Atomic Settlement

Buyer payment is sent to seller and token ownership transfers to buyer in a single transaction.

4

Auto-Delisting

Resale listing is automatically delisted upon successful purchase or cancellation by seller.
